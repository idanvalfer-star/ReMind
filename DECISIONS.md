# Decisions

Choices made while building, with the reasoning. Written as they were made rather than
reconstructed at the end. Reversals are recorded in place, not edited out.

---

## Platform and hosting

**One Worker serves the SPA, the API and the cron.** Cloudflare Pages cannot host Cron
Triggers, so the brief's "Pages + a Worker" is necessarily two deploys on two origins,
requiring CORS and a cross-origin service-worker story. Workers Static Assets is free and
same-origin, which removes all of that. This is a deliberate deviation from the brief.

**`run_worker_first = ["/api/*"]` is load-bearing, not decoration.** Verified against the
routing rules: without it, a *navigation* request to `/api/*` hits the SPA fallback instead
of the Worker. Asset-first routing still applies to everything else, so the Worker is never
woken to serve a static file.

**Plain Vite for the SPA, `wrangler dev` for integration.** There is an official
`@cloudflare/vite-plugin` that runs the Worker inside `vite dev`. Not adopted: the PWA
service worker is the delicate part of this build, and adding a second plugin that also
manipulates the dev server invites conflicts with `vite-plugin-pwa`. Revisit if the
two-command dev loop becomes annoying.

**`vite-plugin-pwa` in `injectManifest` mode, not `generateSW`.** The service worker has to
open Dexie, look a trigger up and compose localised text, so it must be hand-written
TypeScript. Workbox only injects the precache manifest.

**No i18next in the service worker.** It imports the same JSON resources and does a flat key
lookup. A full i18n runtime has no business in a worker that wakes up to show one string.

**Icons are generated by a dependency-free PNG encoder** (`scripts/generate-icons.mjs`).
iOS ignores SVG for `apple-touch-icon`, so real rasters are required; `sharp` is a large
install for six flat geometric images. Maskable variants keep the mark inside the central
40%-radius safe zone.

## Data model

**Client-generated UUIDs everywhere**, not auto-increment. Required so `Trigger.id` can be
handed to the push backend while leaking nothing, and it makes JSON re-import idempotent.

**UTC epoch milliseconds plus a separate IANA zone string.** No `Date` objects and no ISO
strings in the DB: numbers are indexable and range-queryable, the other two are not
reliably.

**Indexed booleans are `0 | 1`.** IndexedDB has no boolean key type. Un-indexed flags
(`isAllDay`, `isPrivate`) stay real booleans.

**A `null` `nextFireAt` is relied upon, not tolerated.** `null` is not a valid IndexedDB
key, so unscheduled triggers fall out of the `[active+nextFireAt]` index automatically and
the due-trigger query never has to filter them. Pinned by a test, because it is silent if it
breaks.

**Three additions to the brief's entity list:**

- `Event.title` — a calendar needs a display label, and it cannot borrow `Entry.body`,
  because editing an event title would rewrite the original phrasing the Entry exists to
  preserve.
- `TriggerFire` — "log every fired trigger with the user's response" needs a table.
- `Settings` / `PushRegistration` singletons.

**`Settings` stores no derived platform state.** Whether the app is running standalone, and
the current notification permission, are read from the platform at the point of use.
Persisting a copy would only guarantee it goes stale. `Settings.onboarding` therefore holds
only genuine user state.

**`TABLE_NAMES` excludes `pushRegistration`.** It drives JSON export, and a push
subscription is per-install: a restored backup must not inherit another install's
subscription.

**Phase 2–4 entities are declared but carry no logic.** One line each, and it avoids a
migration when they land.

## Search

**No search library.** `Entry.searchTokens` is a Dexie `*multiEntry` index, which is a
genuine inverted index. Ranking is a count of matching tokens.

**The same tokeniser runs on both the index and the query.** Indexing and querying must
agree, and the cheapest way to guarantee that is identical code.

**Hebrew prefix particles are stemmed, accepting false positives.** `בירושלים` is one token
meaning "in Jerusalem", so without stripping the particle a search for the bare place name
misses it. Both forms are indexed.

The tradeoff is real and was chosen deliberately: *shin* is itself a particle, so the
4-letter word `שלום` also yields the non-word stem `לום`. Raising the length threshold to
prevent that would also stop `בבית` → `בית` ("in the house" → "house"), which is a query
people actually make. Without a Hebrew lexicon you cannot have both. Junk stems only ever
sit in the index and nobody searches for them, so recall wins.

## Resurfacing engine

**Timezone arithmetic on `Intl` alone, no date library.** `Intl.DateTimeFormat` already
carries the full IANA database and the inverse mapping is about 20 lines. Adding luxon to a
PWA whose selling point is launch speed is a poor trade.

**DST disambiguation matches `Temporal`'s `compatible` rule.** An *ambiguous* wall clock
(clocks went back, the hour happens twice) resolves to the earlier instant; a *nonexistent*
one (clocks went forward) shifts forward past the gap. Both verified against real 2026
transitions in Jerusalem and New York.

**Quiet hours degrade open, never closed.** A disabled, malformed or zero-length window
silences nothing. The failure mode of a badly-timed buzz is one annoyance; the failure mode
of wrongly silencing is a reminder that never arrives.

**"22:00 to 22:00" means no window, not 24 hours of silence.** The other reading makes
scheduling impossible.

**Suppress, never move — reversed from the original decision.** See below.

## Reversal: quiet hours and the cap suppress rather than shift

**Originally:** a reminder landing in quiet hours or over the daily cap was shifted forward
to the first legal instant, on the reasoning that the user asked to be reminded and these
settings govern *when*, not *whether*. Flagged at the time as a user-visible behaviour
change worth confirming.

**Now:** the notification is refused and the reason is returned. `resolveFireTime` either
schedules at *exactly* the requested instant or reports `suppressed`. Reversed at the
owner's direction.

The argument for the new behaviour is the stronger one: a reminder arriving at 07:00 when
the user asked for 22:30 is a notification they did not ask for at a time they did not
choose, and it teaches them not to trust the times they set.

Nothing is silently lost, which is what makes suppression safe:

- The `Entry` is always saved. Capture is never blocked on any of this.
- A suppressed decision carries `suggestion`, the nearest instant that *would* be allowed,
  so the caller can offer it as a one-tap alternative rather than guessing.
- The trigger is simply not created until a legal time is chosen. No "scheduled but muted"
  state has to exist in the schema, so this needed no migration.

The fixpoint loop that used to perform the shift survives as `nearestAllowedInstant`, which
now only ever computes that suggestion. It is still a loop rather than two sequential
checks because the constraints interact: stepping over a full day lands on the next local
midnight, which is itself inside a 22:00–07:00 window.

A daily cap of zero yields `suggestion: null` — the user asking for no notifications at all
is a legitimate setting, not an error, and callers must say so rather than scheduling
anyway.

## Push pipeline

**The wire protocol lives in one module imported by both sides** (`src/shared/pushProtocol.ts`).
Request signing fails in ways that are miserable to debug, almost always because the two
sides canonicalise slightly differently. Sharing the code makes that impossible.

**Per-device ECDSA P-256 keypair, non-extractable, signing every mutating request.** The
Worker is a public endpoint on the internet and the brief specifies no authorisation. A
shared secret compiled into the client bundle is not secret; unguessable ids alone leave the
endpoint spammable. The private half never leaves IndexedDB.

`/api/subscribe` is necessarily unsigned — it is what establishes the key that signs
everything else — so it is the route that needs rate limiting rather than authentication.

**Every route is POST, including `unsubscribe`.** The HTTP method is part of the signed
canonical string, and one shape for all signed calls removes a category of signature
mismatch. Uniformity beat REST aesthetics.

**The canonical string includes the protocol version**, so a future change to the scheme
cannot be replayed as valid under the old one. The body is hashed rather than included, to
keep it a fixed size.

**Reconcile is a full replace, not a diff.** The client's IndexedDB is authoritative, so
sending the whole pending set is simpler than diffing and incapable of drifting.

**IndexedDB is authoritative, so network calls are best-effort.** A failed POST must not roll
back local state; the next reconcile fixes the backend.

**Only triggers due within 30 days are mirrored.** Bounds the reconcile payload. A reminder
set for next year gets mirrored when it comes into range.

**A private Event contributes no notification text at all.** The flag exists to keep the
title off a lock screen, so it is replaced rather than shortened.

**An unknown notification target yields generic text.** `userVisibleOnly` forbids showing
nothing, and iOS evicting IndexedDB makes this a real case rather than a theoretical one.

## Testing

**Vitest with `fake-indexeddb`, engine and parser only.** No UI tests, per the brief.

**`npm test` passing does not mean the code compiles.** Vitest transpiles via esbuild
without typechecking; `tsc -b` has already caught four errors the test suite could not,
including a real one where WebCrypto rejects a `Uint8Array` that might be backed by a
`SharedArrayBuffer`. Both are run before every commit.

**One test asserts `ScheduledPush` has exactly two keys.** If a field is ever added there,
the privacy claim stops being true, and that should fail loudly rather than pass quietly.
